Premise

Two questions, measured two different ways

Almost every sentiment system measures per-comment accuracy and reports it as though it answered the business question. It doesn't, and the gap between the two shapes everything here.

Model questionProduct question
asksIs this review positive?What share of customers are satisfied?
unitOne commentA population of comments
metricAccuracy, macro-F1Estimated prevalence + interval
fails whenIt misclassifiesIts errors are asymmetric

Counting a classifier's positive predictions is biased whenever its errors are asymmetric. The correction is a line of algebra. Everything else exists to make that line trustworthy.

Instances

Three models, because there are three jobs

ModelCorpus · unitLabelsMacro-F1Serves
FR review Allociné films · review Human, binary 0.9195 French demo, v1 complete
EN review Hotel reviews · review Star ratings, 3-class 0.6258 Batch verdict + aggregate
EN sentence Hotel reviews · sentence Machine, 3-class 0.5227 Aspect table + single-review tab

The two English models are not redundant and not a hedge. They were measured on different units and each is used only on the unit it was measured on — the review model never scores a bare sentence, the sentence model never decides a whole review except through an explicit majority-vote rollup.

The French gap (0.92 against 0.63) is not a modelling failure. Allociné carries human binary labels on complete review text; the hotel corpus carries star ratings on fragmentary text, with a middle class that is a rating bucket rather than a linguistic category. Different ceilings, not different effort.

The expensive lesson

Accuracy did not catch the worst bug

Now a permanent fixture

A fixed probe of clean, unambiguous sentences runs in the model notebook and its score is recorded alongside macro-F1. It is cheap, it is not a benchmark, and it is the only check that would have caught this class of failure.

The one probe case still failing is instructive rather than embarrassing: “could not have been more helpful” is praise expressed through a negation, and a bag of n-grams has no way to scope not. That is a limit of the backbone, not of the labels — and the clearest single argument for a transformer.

Contract

The model is not just weights

Temperature, band thresholds and the confusion matrix are learned on specific splits in specific notebooks. They are as much a part of the model as the coefficients, and if they drift apart every output is silently wrong. Each track carries its own versioned config.

Mode is inferred from the label count, not declared, so a config cannot claim one shape and carry another.

Guard

One prediction path

Notebooks and both demos import the same predict(). Writing a softmax inline anywhere else means the contract is already broken.

Guard

Normalisation drift alarm

Loading fails if normalize_version diverges from the code, rather than serving text that differs from what was evaluated.

Guard

No aggregation before measurement

require_aggregation=False lets the aggregate notebook predict in order to measure the correction parameters, while refusing to emit a rate.

Guard

Missing fields name their owner

An unfilled value reports temperature: produced by notebooks/04_calibration instead of a KeyError.

Honest summary

What this architecture bought

The project changed language, corpus, label source, unit of analysis and number of classes. Each of those would normally be a rewrite. They cost notebook re-runs, because the pipeline takes the encoder as a backend, infers its task mode from the data, and keeps every learned constant in a validated config beside the weights.

What the architecture did not buy is immunity from the failure that actually mattered. A clean contract, a sealed test split and a good accuracy number all coexisted happily with a model that had learned the wrong thing. The fix was eight sentences typed by hand.
